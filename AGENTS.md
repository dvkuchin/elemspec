# elemspec — инструкции агенту разработки

`elemspec` — самостоятельный Python-инструмент: детерминированный движок
Gherkin/Playwright, доверенное агентское ядро, stdio MCP-сервер и skill `$new-test`.
Это не приложение 1С:Элемент и не одноразовый генератор Playwright-кода.

## Изменение движка

- До первого стабильного релиза обратную совместимость не сохраняем; пишем чистый
  целевой код. Версия — в `src/elemspec/version.py`.
- Новая Gherkin-фраза: разбор в `steps.py`, действие в `actions.py`, позитивная,
  негативная и неоднозначная проверки, затем синхронизация `docs/language.md` и MCP-контракта.
- Пути именуются относительно корня; не зашивать пути текущей машины в исходники.
- В Bash-скриптах имена переменных только латиницей.

Обычная проверка:

```bash
PYTHONPATH=src .venv/bin/python -m unittest discover -s tests_unit -v
PYTHONPATH=src .venv/bin/python -m elemspec --project examples/getting-started run smoke
```

Живые browser-тесты требуют Chromium и сеть. Рабочие тесты конкретных приложений
живут в отдельных проектах и не используются как регрессия движка.

## Создание UI-теста

Если пользователь вызывает `$new-test`, следовать skill и использовать только MCP
`elemspec`. Не писать `tests/`, `engine-gaps/` и `БЭКЛОГ.md` напрямую. В обычном workspace
можно менять движок только как отдельную задачу; строгий `.elemspec/authoring/` workspace таких прав не имеет.

Агент сам выясняет локаторы и DOM живой разведкой. Автора спрашивают только о
бизнес-требовании, границе тестовой среды и подтверждении найденного дефекта.
