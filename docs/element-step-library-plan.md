# План развития библиотеки шагов 1С:Предприятие.Элемент

## Цель

Довести ElemSpec от smoke-навигации до набора семантических шагов, на котором
первые авторы смогут писать устойчивые тесты форм, списков и обратимого CRUD без
сырого CSS и произвольных пауз.

Движок описывает не предметные операции конкретного приложения (`создать клиента`),
а повторяемое поведение компонентов Элемента: заполнить поле, выбрать значение,
найти строку таблицы, подтвердить диалог, дождаться обновления списка.

## Принципы

- Каждый шаг реализуется вертикально: Gherkin → runtime → семантический локатор →
  browser discovery → evidence → документация → живой тест.
- Устойчивые признаки компонента подтверждаются официальной документацией,
  исходниками вендорских примеров и DOM живого приложения.
- Именованный компонент и платформенная семантика приоритетнее текста; CSS означает
  технический долг.
- Не добавлять шаг только в `steps.py`: ИИ-автор обязан уметь исследовать и доказать
  тот же шаг через MCP.
- DemoCRM служит живым полигоном, но прикладная семантика CRM не попадает в ядро.

## Контрольный пользовательский путь

Первый обязательный вертикальный сценарий — обратимый жизненный цикл клиента:

1. открыть список клиентов;
2. создать запись с уникальным именем;
3. заполнить строковое и ссылочное поле;
4. сохранить и проверить уведомление;
5. найти запись по значению ячейки;
6. открыть, проверить и изменить поле;
7. удалить запись через диалог;
8. проверить отсутствие строки;
9. гарантированно убрать данные и при промежуточном падении.

### Подтверждённые признаки DemoCRM

Живая разведка списка и пустой формы клиента 12 августа 2026 года:

| Семантика | Устойчивые признаки веб-клиента |
| --- | --- |
| Команда создания | `data-testid="create-button"`, `data-component="button"` |
| Поиск списка | `data-testid="list-search-field"`, `data-component="edit"` |
| Именованная таблица | контейнер `data-testid="ОсновнаяТаблица"` с вложенным `data-component="table"` |
| Строка и ячейка | `data-component="table-row"` и `data-component="table-cell"` |
| Колонка | именованный контейнер ячейки, например `data-testid="Наименование"` |
| Поле формы | `data-testid="Наименование"`, `data-component="edit"`, вложенный `base-edit-input` |
| Ошибка поля | вложенный `data-testid="base-editable-message-information"` |
| Записать и закрыть | `data-testid="write-and-close-command"`, `data-component="button"` |
| Список выбора | `data-testid="edit-dropdown-table"` и тот же контракт таблицы |

- [ ] живое доказательство на DemoCRM или другом вендорском приложении;
- [ ] доказанный `green → red → green` прикладного feature-теста.

## Критерий готовности для первых авторов

- [ ] Smoke, навигация, поиск и обратимый CRUD выражаются текущим DSL.
- [ ] Не менее 15 показательных сценариев покрывают формы и списки.
- [ ] Не менее 90% локаторов семантические и не содержат сырого CSS.
- [ ] В итоговых сценариях нет необоснованных фиксированных пауз.
- [ ] Повторные прогоны ключевых сценариев не дают случайных падений.
- [ ] `new_test` сам распознаёт все поддерживаемые компоненты.
- [ ] Неподдерживаемый компонент превращается в структурированный engine gap.
