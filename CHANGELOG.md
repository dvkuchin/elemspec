# История изменений ElemSpec

Здесь фиксируются пользовательские изменения каждой версии движка. Пока проект
не достиг первого стабильного релиза, версии имеют суффикс `.dev0`, а публичные
контракты могут меняться без слоя обратной совместимости.

## 0.17.0.dev0 — в разработке

### Новые возможности

- Добавлен семантический шаг
  `поле "Наименование" имеет ошибку "Required"`. Сообщение ищется строго
  внутри указанного именованного поля; ошибка другого поля не может дать
  ложный зелёный результат.
- Browser API и MCP получили операцию `read-field-error` для живой разведки
  сообщения валидации конкретного поля.
- Evidence-модель агента сохраняет прочитанное сообщение и связь с конкретным
  полем. Один и тот же контракт теперь проходит весь путь от browser discovery
  и MCP до подготовки feature-файла и доказательства сценария.
- Негативная мутация умеет изменять ожидаемый текст ошибки поля и выбирает
  последнюю поддерживаемую бизнес-проверку сценария.

### Изменения поведения

- Клик по `пункт навигации "..."` теперь сначала наводит указатель и ждёт два
  кадра браузера. После этого движок проверяет, что пункт остаётся видимым и
  действительно получает pointer events. Это синхронизирует раскрывающиеся
  подменю 1С:Элемента без `sleep` и без повторного клика.
- `prove` принимает негативный прогон только тогда, когда со снимком упал именно
  мутированный шаг. Случайное падение более раннего шага больше не считается
  доказанным красным результатом.
- CLI, MCP и навык `$new-test` используют единое поведение проверки ошибки поля;
  новая возможность доступна не только при ручном запуске feature-файла, но и
  в полном агентском процессе создания теста.

### Исправления

- Временная ошибка Playwright во время асинхронной навигации больше не завершает
  browser discovery: агент получает ошибку одной операции и может запросить
  новый snapshot в той же сессии.
- Устранена гонка раскрытия подменю DemoCRM, при которой визуально найденный
  пункт `Clients` иногда закрывался без перехода. Исправление подтверждено
  браузерным регрессионным тестом и серией живых прогонов.

### Развитие агентского контура

- Обновлены правила `$new-test`: агент должен исследовать ошибку именованного
  поля через `read-field-error`, использовать семантический шаг и доказывать
  его негативной мутацией.
- Browser discovery после временной ошибки одной операции остаётся доступным:
  агент может запросить новый snapshot и продолжить работу в той же сессии.
- Доказательство `green → red → green` защищено от ложного результата, когда
  негативный прогон стал красным из-за нестабильного или более раннего шага.

### Тесты и документация

- Добавлены unit-, browser-, MCP-, evidence-, mutation- и proof-тесты нового
  сквозного поведения.
- Добавлен браузерный регрессионный тест подменю, которое начинает принимать
  клик только после наведения и завершения двух кадров отрисовки.
- Актуализированы README, описание языка и архитектуры, руководство по
  использованию, план Element-библиотеки и обе поставляемые копии навыка.
- Создан этот журнал изменений; `CHANGELOG.md` включён в исходный
  дистрибутив ElemSpec.

### Проверка

- Unit-тесты и сборка wheel проверяются CI на Python 3.11–3.13; локальный
  полный прогон версии, включая Chromium и live smoke, выполнен на Python 3.11.
- Полный локальный набор содержит 185 успешно выполненных тестов. Исправление
  навигации дополнительно проверено серией из 10 последовательных живых
  прогонов DemoCRM с видеозаписью падений.
- Живой сценарий обязательности имени клиента DemoCRM доказан через
  `green → red → green` с семантическим локатором поля.
